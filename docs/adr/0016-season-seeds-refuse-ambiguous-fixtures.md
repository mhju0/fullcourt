# ADR 0016: 시즌 시더는 모호한 경기와 기존 결과 수정을 거절한다

상태: 수용, 2026-10-22. 운영 데이터 실행은 포함하지 않는다.

## 확인한 문제

`seed_season_from_hoopr.ts`는 원정팀·원정 점수·홈팀·홈 점수로 ESPN 날짜를
연결했다. 실제 2003-04의 `0020300652`, `0020301107`은 모두 SAC 99 @ HOU 94지만
서로 다른 경기다. 먼저 완료된 HTTP 응답의 날짜를 보관하면 두 경기에 같은 날짜가
붙고, 기존 upsert는 올바른 날짜도 덮어쓸 수 있었다.

## 결정

- hoopR 매칭 키가 중복되면 네트워크 요청 전에 중단한다. ESPN 관측은 event ID와
  Eastern 날짜를 확인하며, 모호한 후보·상충하는 관측·수집 실패를 추측으로 메우지 않는다.
- 과거 시즌 시더는 누락 경기만 삽입한다. 동일 ID의 경기 식별 정보·유형·final 결과가
  같으면 아무것도 쓰지 않는다. 다른 ID의 같은 경기, 바뀐 날짜·팀·점수·상태는 전체
  계획을 거절한다. 수정은 검토된 correction/rekey 경로에서 파생 데이터와 함께 처리한다.
- 기존 데이터 검사와 모든 삽입 chunk는 하나의 transaction에 둔다. 먼저 `games`의
  `SHARE ROW EXCLUSIVE` lock을 획득해 검사와 삽입 사이 다른 writer의 변경을 막는다.
  실패하면 앞선 chunk까지 rollback한다. 이 lock은 수동 시더의 짧은 쓰기 구간에만 사용한다.
- upcoming 시더는 현대 정규시즌 전체 일정용이다. 수집 실패가 있으면 중단하고,
  30팀 모두 정규시즌 경기 수가 80 또는 82로 같아야 한다. Cup final은 별도로 다룬다.
  짧은 과거 시즌이나 부분 일정은 이 경로에서 추측해 허용하지 않는다.
- 두 시더 모두 새 복제본에서 캐시 상위 폴더를 만들 수 있어야 한다.

## 검증과 한계

매칭·일정 계약 테스트와 별도의 실제 PostgreSQL에서 중복 거절, 동일 입력 no-op,
후반 chunk 실패 rollback, 기존 행 보존, 동시 writer 직렬화를 검증한다. 이 검증은
운영 DB 적용이나 아직 수집하지 않은 시즌의 원본 정확성을 증명하지 않는다.
