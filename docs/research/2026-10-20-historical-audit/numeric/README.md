# 전체 저장 시즌 수치 감사 (2026-10-20)

읽기 전용 `REPEATABLE READ` 한 트랜잭션으로 1985-86~2026-27의 42개 저장 시즌, 51,695경기, 103,390개 최신 팀별 점수, 30개 팀을 확보했다. 최종 경기 50,495개와 예정 경기 1,200개가 있다. 점수 중복행과 최신 시각 동률은 모두 0개다. `snapshot-manifest.json`에 트랜잭션 시각, 원본 커밋, 원본 파일 SHA-256을 남겼다. DB 수정, 재채점 저장, 계수 변경, 공개 생성물 수정은 하지 않았다.

## 확인된 결과

- 현재 실제 `scoreGameFatigue`와 `rowToRecentGame`으로 모든 103,390개 팀 경기를 재실행했다. 점수와 저장되는 16개 구성요소·문맥 필드에서 **1,757,630개 비교가 모두 일치**했고 실행 실패는 0개였다. 저장값이 현재 엔진과 다르다는 증거는 없다.
- 별도 Python 날짜·구면거리 오라클로 저장 필드 827,120개, 엔진 필드 930,510개를 검사했다. 일정 밀도, 휴식 간격, B2B, 3-in-4, 4-in-6, 7일 이동거리는 모두 일치했다. 이는 기록된 경기장 가정에 따른 계산 검증이며 실제 비행 경로 검증은 아니다.
- 공통 `venueStreak` 의미 오류가 있다. 실제 홈 경기인데 이전 원정 연속횟수가 남는 **25,046개** 팀 경기와, 원정 경기인데 이전 홈 연속횟수가 남는 **25,095개** 엔진 `homeStandLength`가 있다. 첫 번째는 저장값과 현재 엔진 양쪽에 존재한다. 두 번째는 점수에 쓰이지 않는 피처다. 원정횟수 1~2는 무료 구간이므로 모든 횟수 오류가 점수 오류를 뜻하지 않는다.
- 홈 복귀 때 현재 원정횟수를 0으로 보는 진단 시나리오에서 홈 점수가 낮아지는 경기는 전체 6,612개, 공개 결과 표본 6,125개다. 최대 하락은 2011-02-26 경기 20792의 4.41점(11.40→6.99)이다. 이 시나리오는 엔진이 반환한 구성요소와 기존 반올림 순서를 유지하면서 홈 원정 연속 부하만 제거했으며 나머지 입력·계수·분류선은 고정했다.

## 공개 결과 영향

공개 집계는 정규시즌 + 정상 구간 + 최종 점수 있는 final + 비중립 경기에 한정했다. 2019-20 버블을 제외하되 1998-99·2020-21의 5월 경기는 유지했다. 실제 사용한 47,112개 표본과 현재 홈 호출 27,420개/16,778승, 5+ 호출 3,756개/2,452승은 기존 생성된 사실과 정확히 일치한다. 미래 2026-27 결과는 섞지 않았다.

| 구간 | 현재 호출/승 | 홈 원정횟수 0 진단 호출/승 | 승률 변화 | 해당 구간 홈 기준선 |
|---|---:|---:|---:|---:|
| 전체, 홈 휴식 우위 0.5+ | 27,420 / 16,778 | 28,151 / 17,212 | 61.1889% → 61.1417% | 59.9295% |
| 전체, 홈 휴식 우위 3+ | 10,463 / 6,603 | 10,754 / 6,778 | 63.1081% → 63.0277% | 59.9295% |
| 전체, 홈 휴식 우위 5+ | 3,756 / 2,452 | 3,887 / 2,537 | 65.2822% → 65.2688% | 59.9295% |
| 최근 10시즌, 홈 휴식 우위 0.5+ | 6,386 / 3,720 | 6,605 / 3,840 | 58.2524% → 58.1378% | 56.2195% |
| 최근 10시즌, 홈 휴식 우위 3+ | 1,942 / 1,189 | 1,999 / 1,221 | 61.2255% → 61.0805% | 56.2195% |
| 최근 10시즌, 홈 휴식 우위 5+ | 555 / 340 | 582 / 356 | 61.2613% → 61.1684% | 56.2195% |

전체 홈 호출은 기존 27,420개가 모두 유지되고 731개가 추가되며 빠지는 호출은 없다. 최근 10시즌(2016-17~2025-26)은 기존 6,386개 유지, 219개 추가다. 전체 헤드라인은 소수점 한 자리 표시에서 **61.2%→61.1%**로 바뀐다. 기준선 대비 상승폭은 +1.2594pp→+1.2122pp다. 더 많은 홈 호출이 생기지만 평균 승률은 약간 낮아지는 선택 표본 변화다. 예측력 개선이나 원정 이동의 인과효과 증거로 해석하지 않는다.

방문팀 휴식 우위는 11,494개/4,867승(42.3438%)→10,648개/4,522승(42.4681%)이다. 방문팀 기준선은 40.0705%다. 원정 우위를 헤드라인에 합치지 않았다.

공개 표본에서 우위 방향 분류는 1,484경기, 절댓값 크기 분류(neutral/small/medium/large)는 2,201경기, 절댓값 3+ 소속은 597경기, 5+ 소속은 219경기에서 바뀐다. 각 수치는 서로 겹칠 수 있는 경기 수이며 합쳐서 별개 경기 수로 쓰면 안 된다. 방향별 3+/5+ 호출 추가·제거 수는 `selection-transitions.csv`에 별도로 있다.

## 범위와 남은 불확실성

선행 경기 문맥은 시즌이나 정규시즌 여부로 자르지 않고 `[대상일−30일, 대상일)`의 모든 경기 종류를 읽었다. final 대상은 final 선행 경기, 예정 대상은 final/scheduled/live 선행 경기를 사용했다. 실제 final 연장전·점수차·팁오프를 유지하고 미완료 선행 경기에서만 연장전과 점수차를 중립화했다. 결과 입력이 실제 점수를 바꾸는지 `verify.mjs`의 독립 fixture로 확인했다. held 상태는 스냅샷에 없으며 향후 존재하면 결과 표본에는 포함하지 않고 재실행 자체만 진단으로 취급한다.

`days_since_last_game=null`(30일 문맥 없음), score=0, missing score를 시즌별로 분리했다. 저장 피로도에는 엔진 버전 열이 없으므로 버전 이력을 추정하지 않았다. 모든 저장행이 현 소스와 일치한다는 관찰과 시즌별 `computed_at` 범위만 기록했다.

사실 입력 정확성은 아직 별도 문제다. ADR 0003에 따라 과거 OT=0은 연장전 없음으로 검증된 값이 아니고, 과거 neutral=false도 일반 경기장 개최로 검증된 값이 아니다. 원본 날짜·연장전·팁오프·경기장 외부 대조는 다른 감사 파트의 결과를 함께 봐야 한다. 기록된 경기장·직행 구간 가정에서 산술이 일치한다는 결과로 귀가 여부, 실제 항공 이동, 누락된 과거 중립 경기까지 정상 판정할 수 없다.

수정은 가능하다. 공통 streak 함수가 현재 장소와 반대되는 연속횟수는 0이 되도록 고친 뒤 동일 스냅샷으로 의미 검증과 영향 재집계를 해야 한다. 피로도 값 변화는 홈 팀에 한정되지만, 연관 predictions/캐시/생성물과 완료된 예측 기록 정책을 포함한 별도 정합성 계획이 필요하다. 완료된 과거 예측 기록을 소급 변경한다고 가정하지 않으며, 저장 변경은 통제된 별도 절차와 독립 검토·승인을 거쳐야 한다. 공개 rest-split/ablation/기타 파생 수치는 해당 생성기로 다시 만들고 고정 테스트를 맞춰야 한다. 이 감사에서는 수정이나 재생성을 실행하지 않았다.

## 산출물과 재현

- `season-counts.csv`: 42개 시즌 전수 커버리지, 결측과 0 구분, 의미 오류·분류 변경, 계산 시각.
- `season-outcomes.csv`: 모든 저장 시즌의 시나리오/방향/크기/누적기준선별 호출·승·승률·장소 기준선. 결과가 없는 시즌은 공란 승률로 남김.
- `period-outcomes.csv`, `selection-transitions.csv`: 전체·최근 10시즌 비교 및 retained/added/lost.
- `oracle-per-season.csv`, `oracle-summary.json`, `replay-summary.json`, `summary.json`: 산술·의미 검증 집계.
- 무시된 `docs/audit/2026-10-20-historical-audit/snapshot/`: 원본 전체 gzip JSONL, 전수 재실행, 전수 오라클, 모든 이상행, 진단 영향행. `artifact-manifest.json`의 해시로 연결한다.
