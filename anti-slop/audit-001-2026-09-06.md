# FullCourt antislop audit

Baseline: `4329637`. Audit first, then apply, as authorized by the owner on 2026-09-06. Project setup installs the core and all five companion skills from the existing local installation, without downloads or Claude harness migration.

## Scope and direction

Source and existing browser tests lead the review. Live inspection used the populated local app at `http://localhost:3107`, Chromium, 360px phone width, and desktop width. The existing accessibility and document-overflow suites cover all 20 published routes at 390px and 1440px. Additional checks inspect focused controls and touch target geometry, which those suites do not cover.

Reading this as a basketball analytics tool for readers comparing schedule effects with actual results, in the existing Front Office visual language: ENERGY 2 / RHYTHM 2 / MOTION 2. The initial app estimate of MOTION 1 was revised after inspecting its existing route cross-fades; the front page also uses short, one-time reveals. These are audit interpretations of the existing direction, not a new brand decision.

`docs/design/BRAND_GRAMMAR.md` provides the direction. The light app, dark front page, Geist family, rose/teal data poles, indigo accent, court mark, and table composition have documented purposes. They are not defects simply because the skill lists similar techniques as warning signs. Existing authored scientific prose supplies voice context; an isolated em dash is not evidence of generic copy, per the copywriting skill's voice calibration and false-positive guidance. Published figures, model coefficients, names, and analytical claims are outside stylistic rewriting.

## Findings

1. **HIGH, R-32: Keyboard focus disappears on navigation controls and the palette input.** At 1280px, focused SEARCH and OTHER both match `:focus-visible` but compute to `outline-style: none`, `outline-width: 0px`, and no box shadow. At 360px the focused command input also has no outline. `src/app/globals.css` places the shared indicator in `@layer base`, below component `outline-none` utilities and the unlayered `[cmdk-input]` rule. Keep a shared indicator at a cascade level those resets cannot erase; inset it where the palette container clips its children.

2. **HIGH, R-03: Shared mobile controls miss the 44px touch target required by this filter.** Live measurements at 360px: reference-section links 27px high, command results 34px, shot-value mode buttons 36px, upcoming-edge buttons 39px, season selectors/month buttons 42px, and the home link 22px. The games board's arrow and density buttons and sortable table headings are also undersized. Footer links share a cramped row. Establish a phone/tablet target floor for controls and navigation, enlarge the method and front-page entry links, and let footer groups wrap. Checkbox targets should include their labels; inline links inside prose should retain text flow.

3. **HIGH, R-03 and C-4: The mobile command input misses the existing 16px input font floor.** `[cmdk-input]` computes to 15px at 360px, while FullCourt already uses 16px for phone inputs to avoid focus zoom. Give this input the same floor when mobile navigation is active. This finding is a measured CSS inconsistency; actual iOS keyboard/zoom behavior was not exercised in Chromium.

4. **LOW, R-31 and antislop-code: Shared shell comments repeat maintenance history and decorate section headings.** Four footer links repeat the same three-line explanation of a past hover fix, and `globals.css` uses box-drawn comment banners. Keep the useful cascade explanation once and use plain section headings. Preserve comments explaining brand intent, analytical assumptions, accessibility behavior, and non-obvious browser constraints.

5. **HIGH, R-03: Long headline figures overflow at 320px.** The additional narrow-width sweep found 43px of document overflow on `/playoffs`. `StatFigure` renders the equal-rest count and grind-gap figure with fixed 40px type and `white-space: nowrap`; the count's text spans 330px inside a 254px content box. The element's bounding box still fits, so only checking element bounds misses the overflowing text. Scale headline figures down on narrow screens while preserving their value, one-line reading, and desktop size. This finding was recorded before changing the figure component.

## What the audit did not flag

- No document overflow or uncaught JavaScript exceptions in the manual 360px sweep of the front page, nine product routes, and reference overview.
- The UI has product-specific tables, methodology links, real data provenance, and published null results. No fake testimonials, invented customer metrics, generic pricing grid, or dead marketing form was found.
- Uniform data rows serve comparison. Court geometry identifies the product. Navigation icons name their destinations. Shadows mark overlays. The existing brand record supplies purpose rather than requiring new decoration.
- Data views have loading/error/empty handling in source. The optional Edges Ahead strip deliberately disappears when unavailable, an existing product decision that this audit does not reverse.
- No new assets, routes, theme toggle, palette, or analytics methodology are proposed.

This is a findings report, not a whole-product Delivery Gate PASS. The follow-up records the applied changes, browser evidence, checks, and remaining verification limits.
