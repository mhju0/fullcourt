# Audit 002: product explanations

The owner requested a complete copy scan and application of antislop to the GitHub description, README, and explanations throughout the app, especially Behind the Data. The existing audit-then-apply mode continues. This request explicitly includes existing prose; the previous audit's decision to leave it alone does not apply here.

## Findings

1. HIGH, R-02: Em dashes appear throughout descriptions, methodology prose, tooltips, and metadata. Rewrite sentences rather than substituting punctuation mechanically.
2. LOW, R-16 and C-3: The README repeats the product inventory, methodology, and development history. Its image alt text includes whole analyses. Give each topic one place and describe screenshots concisely.
3. HIGH, R-36 and C-5: Some explanations overstate evidence. A time-zone null is described as proof that travel costs nothing; an observational control is described as disproving an absence explanation; the site says no picks use team strength even though the separate playoff model uses records.
4. LOW, R-16 and R-31: Repeated declarations of honesty, dramatic conclusions, and personified models obscure the method and its limits. State the measurement and result directly.
5. HIGH, R-38: README descriptions retain retired controls, stale labels, and unqualified predictions. Align explanations with source and link current figures to their maintained pages.

These findings were identified from the source and README before rewriting. Review covers public text in pages, components, and library copy, all ten Behind the Data routes, the README, and current documentation. Historical specifications, research protocols, and decisions remain historical records. Preserve numerical expressions, formulas, identifiers, generated artifacts, and evaluation rules.

Visual direction remains Front Office, ENERGY 2 / RHYTHM 2 / MOTION 2. Coverage, examples, publishing status, and verification will be recorded in the follow-up.
